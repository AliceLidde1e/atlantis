## 1. 目的と対象

### 2026-10-24 画面改善

- 英語キャッチコピーは **Known Cards. Unknown Horizons.**。ホーム紹介文は「ATLANTISへようこそ。このサイトは、旧枠モダンの入賞デッキ閲覧やカード検索ができるポータルサイトです。」とする。
- 詳細モーダルの閉じるボタン用の帯を廃止し、右上の `CLOSE×` と内容を同じ上端から表示する。Settings・Menu等の操作ボタンも同じ色・枠・フォントを使う。
- デッキやMy Decksからカード詳細へ移動したときは `BACK` で元の詳細・スクロール位置・表示形式へ戻れる。関連デッキへの移動も履歴に保持し、ブラウザの戻るにも対応する。`CLOSE×` は詳細表示の開始元ページへ戻る。
- Cardsの検索・絞り込みは常時表示。PCはコンテンツ左端の追従サイドバー、タブレット・スマートフォンは結果上部の通常フローに配置する。スマートフォンでは条件欄内部のスクロールを設けない。DecksのFilters開閉は維持する。
- Cardsは結果の上部にも件数・ページ送り・Printingを表示し、下部のページ送りと同期する。DisplayはImages／Listのプルダウンとし、表示切替でも検索条件・ソート・ページ位置を維持する。
- OR／Exactの説明と日本語補助検索の対応表は「検索方法」に集約する。Decks・CardsのBlackは他の色と同じ背景とし、文字だけを黒塗り・白い縁取りにする。

ATLANTISは、旧枠モダンのカードと掲載デッキを探し、手元のデッキをブラウザ内で扱う非公式ファンサイト。閲覧者のログインは不要。まずURLを知るメンバーに共有して実機で試す。

- リポジトリ：<https://github.com/AliceLidde1e/atlantis>
- テスト用Webアプリ：<https://alicelidde1e.github.io/atlantis/>
- 配信対象：リポジトリの `site/`。`main` へのpushで検査し、GitHub Actionsの手動ワークフローでPagesへ配信する。
- 公開境界：GitHub PagesのURLは誰でも開ける。`noindex,nofollow` は検索エンジンへの依頼であり、アクセス制限ではない。秘密情報・掲載許可の内部記録・個人のデッキを公開リポジトリへ置かない。

## 2. 採用済みの方針

1. カード集合は現在の基準クエリ `f:modern is:old year<=2003` で取得・照合した **1,015種類**を用いる。カードの共通識別子はOracle ID。集合の変更は自動承認せず、再照合する。
2. 掲載デッキと大会案内は管理側の静的データとして配信する。一般利用者がサイト上で掲載内容を書き換える機能は設けない。
3. マイデッキはブラウザ内に保存する。サーバー保存・アカウント間同期はない。端末・ブラウザ・公開URLを変えると自動移行されないため、JSONバックアップ等で移す。
4. MO画面の保存はIndexedDBで、通常のマイデッキとは別領域。Scryfall検索とカード画像・印刷版の取得には通信が必要。
5. 本番相当の外観は博物館風の深緑・真鍮色・額縁・金属風ロゴを基調とする。英語大見出し・ボタン・タブは **Iceberg**、日本語見出し・解説・記事本文は **Shippori Mincho（しっぽり明朝）**、検索・デッキエディタ等の実用日本語UIは **Zen Kaku Gothic New** を使う。数値・補助データは必要に応じて等幅書体を使用する。3書体のWOFF2とSIL Open Font License 1.1許諾文を同梱し、`site/typography.css`で通常・MO両画面に適用する。CgWoodBlockの配信・ローカル参照は採用しない。
6. サイトには対象外の組織・サービス名を表示しない。サービスは無料の非公式ファンサイトとして扱い、権利・出典表示を維持する。

## 4. 掲載デッキの受入条件

- 提供してもらうもの：デッキ名、公開する作者名、メイン／サイドのカード名と枚数、短い紹介文。任意でアーキタイプ、サイドプラン、代表カード、Featured Decksへの掲載希望。
- 運営が確認するもの：作者・出典・掲載許可、カード名と対象集合の照合、枚数、英語書出しテキストと画面の一致。実績や大会結果は確認できた場合だけ記載する。
- 2026-10-24：提供Excelの戦績欄がある48件へ置換。既存サンプル8件と戦績空欄59件は非掲載。大会種別・場所・戦績・公開プレイヤー名はExcelに従う。記録日は大会開催日と区別する。Featured Decksは掲載データから選ぶ。検査では大会情報、カード集合、枚数、英語書出しの一致を確認する。
- NOTE-01とNOTE-02のテキスト参照は別アーキタイプを指していたため、同梱リストの特徴カード・枚数により、それぞれdeck_08.txt（トリコ・エンジェル）、deck_07.txt（青赤緑アサルト）へ対応付けた。Excelの未判読カード候補は採用せず、同梱の完成テキストを使用。
- My Decksに保存したデッキは端末内データであり、自動的に掲載デッキへ公開されない。掲載前に本人が明示的に提出し、管理側が確認する。
- 掲載許可や連絡先の内部記録を `site/` や公開リポジトリに含めない。

## 7. 別スレッドでの再開手順

1. この文書と[README](../README.md)を読む。現行ソースは上記リポジトリの `main`。
2. `site/` と `check_site.py`、対象機能のJS、Actionsを確認し、作業前にGitの差分と最新配信runを確認する。
3. 変更後は `python check_site.py` と4つの `node --check`、必要なUI検証を行う。`main` へのpushだけでは公開ページは更新されない。Actionsの **Deploy ATLANTIS closed test → Run workflow** を実行し、成功後に公開URLを再確認する。
4. Androidやメンバーの結果は、実際に確認した端末・日時・URL・操作・結果を記録する。未実施を合格扱いしない。
5. 正式掲載デッキはリストと公開許可がそろってから追加する。My Decksのローカルデータを本人の依頼なく取得・公開しない。
